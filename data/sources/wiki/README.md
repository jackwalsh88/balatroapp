# Wiki source drop-zone

`balatrowiki.org` is unreachable from the build environment - the egress proxy
returns `EGRESS_BLOCKED` for both `curl` and the fetch tool - so its pages are
fetched by hand and committed here.

**This has been done.** `jokers.html` is the rendered Jokers table and is the
source of every joker's effect text, type and activation.

Everything here is committed **verbatim, unmodified**. That is the point: the
joker table's semantics are auditable against a file in the repo rather than
against someone's memory of a web page.

## What is here

| File | What it provides |
|---|---|
| `jokers.html` | The rendered DPL table: effect text, cost, unlock, type (+c/+m/Xm/...), and activation (Independent / On Scored / On Held / ...). 150 rows. |
| `jokers.wikitext` | The page source. Kept for provenance, but it carries **no per-joker data** - the table is generated by a DynamicPageList query, so the wikitext holds the query rather than its results. |
| `PAGES-all-150.txt` | Page names, retained in case individual joker pages are ever needed. |
| `PAGES-67-missing.txt` | Historical: the jokers that lacked effect data before this import. |

The constants do **not** come from here. They come from
`../game/jokerdata.lua`, extracted from `game.lua`'s
`Game:init_item_prototypes()`. The wiki supplies meaning; the game supplies
numbers. Where the wiki prose quotes a number, it is checked against the
game's `config` rather than trusted.

## Refreshing after a game update

1. Re-extract `jokerdata.lua` from the new `game.lua`.
2. Re-save the Jokers page as `jokers.html` (Save Page As -> "Web Page, HTML Only").
3. `python tools/parse_sources.py && python tools/rebuild_table.py && python tools/model_effects.py`
4. `pytest` - the joker-table tests will report any joker whose key, name,
   rarity or cost moved, and any newly added joker will show up as unmodelled
   rather than silently missing.

## What the wiki is NOT used for

Spec §9 records two mechanics the wikis could not settle - whether holding a
consumable excludes it from the pool, and Blueprint/Brainstorm ordering. Those
remain `unresolved` in `data/mechanics.json` regardless of what this page
asserts. They resolve by reading the game's pool logic, not by reading a wiki.
